# Mappings Contract

## CURRENT

Mapping is a standalone logging domain. Retailer and Distributor values may be selected from the canonical client suggestions shared by Call Logs and Client Query or entered as faithful free text. A suggestion is discovery, not validation authority. Mapping requests and historical mappings use stable IDs and explicit requester/completer attribution. The creator may edit Pending or Completed business values and may complete, reopen, or recomplete the same request. Team KPI reads compatible current completion sources.

## INVARIANT

Stable request/mapping IDs, exact trimmed display values, timestamps, and explicit employee ownership are preserved. Mapping never creates Leads, invokes Pipeline Lead creation, or transitions Pipeline stages. Cross-domain write delta is zero. Completed work is not double counted or fabricated.

`requested_by` is the immutable creator and sole mutation authority. Readers, including Admin, are not automatically writers; Admin may edit only an Admin-created Mapping. `mapped_by` and completion time are generated by the database only when the creator transitions into Completed. An edit that stays Completed preserves them. Reopening clears the current completion facts, and recompleting records the real new transition. UUIDs are identity authority; display snapshots are audit fallback only.

Offline creator edits update the exact Dexie row and coalesce into `mapping-update:<request_id>` as UPDATE, never INSERT. A terminal ownership/RLS denial is retained for review and does not retry forever.

## CHANGE BUDGET

DATA AUTHORITY: `public.mapping_requests`. READ BUDGET: at most 50 normal list rows; no population scan for cards. WRITE BUDGET: one exact Mapping UPDATE and zero cross-domain writes. RLS MODEL: existing capability plus `requested_by=auth.uid()`. INDEX REQUIREMENTS: existing identity/visibility indexes; no speculative index. FAILURE MODE: durable local row and review-required terminal queue state. CONCURRENCY MODEL: stable-ID latest queued creator edit wins. IDEMPOTENCY MODEL: stable request/update keys and exact `request_id`. TEST PLAN: trigger/RLS matrix, offline convergence, KPI lifecycle, and Mapping E2E.

## KNOWN DEBT

Canonical and legacy completion shapes coexist. Historical relational-only rows may display their retained Lead reference when no free-text display value exists.

Primary tests: `mappingStandaloneContract`, `product-054-postgres`, Mapping E2E, and Team KPI aggregation tests.
