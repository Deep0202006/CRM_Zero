# Prompting

Future prompts should state the desired outcome, visible bug or feature, and genuinely unusual constraints. They should not repeat architecture, test commands, zero-deletion rules, deployment/rollback workflow, standard production safety, or documented domain semantics; the harness owns those.

Agents load only:

1. root `AGENTS.md`;
2. task risk and scope;
3. relevant contract;
4. relevant skill;
5. relevant code and tests.

Do not preload every contract or demand token-heavy mandatory narratives. Concise evidence and repository artifacts are preferred.
