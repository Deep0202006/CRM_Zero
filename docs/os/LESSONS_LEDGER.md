# Engineering Lessons Ledger

Record only genuinely new, reusable engineering knowledge from serious incidents. Do not include customer data, credentials, or verbose incident narratives.

| Date | Domain | Symptom | Wrong assumption / missing capability | Permanent lesson | Contract/guard/test/skill updated | Status |
|---|---|---|---|---|---|---|
| 2026-08-10 | Calls | Free-text clients stayed local and new calls waited behind old queue failures. | UI client references, offline repair, and server validation did not share one semantic contract; the outbox lacked exact-item priority confirmation. | UI client-reference semantics, offline payload semantics and server validation must share one canonical contract. Custom user-entered identities must never be silently interpreted as relational UUID identifiers. Critical new work should receive targeted confirmation through its existing durable outbox when backlog order is not a business dependency. | Calls contract and critical flow; client/sync/priority regression tests; Calls and Incident skills. A pattern guard was not suitable for this semantic rule. | Implemented |
| 2026-08-10 | Owner production safety | Production testing could be interpreted as permission to create and later delete dummy business records. | The harness prohibited fabricated records generally but did not state that cleanup does not make a live production test write safe. | Automated tests, QA fixtures, and smoke tests must never create dummy/test business data in live production Supabase. Production verification is read-only unless the owner explicitly authorizes the exact mutation. Use mocks, isolated fixtures, local/preview environments, and read-only reconciliation; never insert dummy data and then delete it. | Golden Principles, production-safety skill, release guidance, invariant guard, and harness self-test. | Permanent owner constraint |
| 2026-08-10 | Calls | Confirmed calls visible in Admin KPI could disappear from employee Call Logs. | Critical business history and optional derived metrics shared one all-or-nothing failure boundary; the local fallback did not expose degraded authority. | Critical business-history reads must not share an all-or-nothing failure boundary with optional derived metrics. Metric failure may degrade metrics but must never suppress successfully retrieved authoritative records. | Calls contract, `callHistoryAuthority` regression suite, and incident note. Regex guard declined as semantically brittle. | Implemented |
| 2026-08-10 | Pipeline | Offline or failed stage transitions can later overwrite newer server state. | A business transition was treated as a generic row update, so the durable outbox lost its expected-stage precondition and replay disabled concurrency checks. | Durable state-machine work must preserve the command’s identity, expected state, target state, actor, and conflict outcome. A generic row patch is not a safe retry contract for a business transition. | Pipeline contract, semantic outbox, server-boundary migration, UI state, and regression tests. | Implemented; migration approval pending |
| 2026-08-10 | Engineering OS / Pipeline | Pipeline verification omitted the real employee board. | The domain map referenced stale `src/app/pipeline/` while production UI lived at `src/app/onboarding/`. | Domain automation must map the actual production route/code surface; stale path mappings can let critical UI logic escape domain verification. | Pipeline harness paths/tests and concise `zd-pipeline` skill. | Implemented |
